# TripForm i18n 実装計画

## 目的
TripForm コンポーネントのラベル・プレースホルダー・バリデーションメッセージを国際化し、日英両対応のフォーム体験を提供する。フォームに依存する関連コンポーネントとの整合性も確保する。

## スコープ
- `travel-journal/src/components/TripForm.jsx`
- `travel-journal/src/i18n/locales/ja/` および `travel-journal/src/i18n/locales/en/`
- バリデーションロジック（必要に応じて `utils` 配下）

## 実装ステップ
1. **現状調査**
   - TripForm 内の固定文言・ステータス選択肢・エラーメッセージを洗い出し、翻訳キー案を作成。
   - 既存の `TripList`, `TripDetail` などと共通化できるキーの有無を確認。

2. **辞書整備**
   - `src/i18n/locales/ja/tripForm.json`, `src/i18n/locales/en/tripForm.json` を新設。
   - 上記ファイルにフォーム要素（ラベル、プレースホルダー、ボタン、エラー文言）を定義し、必要なら共通辞書 `common` に移す。
   - `src/i18n/index.js` に `tripForm` ネームスペースを登録。

3. **コンポーネント改修**
   - `TripForm.jsx` で `useTranslation('tripForm')` を導入。
   - ラベルやヘルプテキストをキー参照へ置換。
   - 選択肢リストを `t()` の戻り値（オブジェクト/配列）から生成するよう変更。
   - バリデーションメッセージを `t()` 経由に書き換え。ロジックがフォーム外にある場合は翻訳キーを渡せる設計に調整。

4. **UI 確認**
   - 日本語/英語の両ロケールでフォーム表示を手動確認。
   - 既存機能（新規作成・編集・キャンセル）に影響がないか動作テスト。

5. **リファクタリング & 共有**
   - 重複文言がある場合は共通ネームスペースへ集約。
   - 実装内容と確認結果を学習ログに整理。

## リスクと留意点
- フォーム外のエラーハンドリングが文字列を直接埋め込んでいる場合、追加対応が必要。
- 選択肢コード値と表示文言が分離されるため、保存時に影響しないかテストが必須。
- `npm install` が未完了のため、依存調整後にロックファイル更新を忘れない。
