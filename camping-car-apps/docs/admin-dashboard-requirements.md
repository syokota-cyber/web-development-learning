# 📊 管理ダッシュボード要件定義書

## 1. 概要

### 1.1 目的
キャンピングカー旅行記録アプリケーションの運用状況をモニタリングし、システムの健全性とユーザー動向を把握するための管理画面を構築する。

### 1.2 スコープ
- **Phase 1（初期実装）**: 基本的な統計表示とシステム監視
- **Phase 2（将来拡張）**: リアルタイム更新と高度な分析機能

### 1.3 想定利用者
- システム管理者（横田様）
- 将来的には運用チームメンバー

---

## 2. 機能要件

### 2.1 必須機能（Phase 1）

#### 2.1.1 ユーザー統計
- **総ユーザー数**: 登録済みユーザーの総数表示
- **アクティブユーザー数**: 過去7日間にアクセスしたユーザー数
- **新規登録数**: 日別・月別の新規登録推移
- **ユーザー増加率**: 前月比・前週比の増加率

#### 2.1.2 システム監視
- **システム状態**: データベース接続状態のリアルタイム監視
- **エラーログ**: 最新のエラー情報表示（最大10件）
- **API応答時間**: Supabase APIの応答速度モニタリング
- **ストレージ使用量**: データベース・ファイルストレージの使用状況

#### 2.1.3 コンテンツ統計
- **総旅行記録数**: 作成された旅行記録の総数
- **月別投稿数**: 月ごとの旅行記録作成数推移
- **平均滞在日数**: 旅行の平均日数統計
- **人気の目的地**: よく選ばれる目的地TOP10

#### 2.1.4 アクセス制御
- **管理者認証**: 特定のメールアドレスのみアクセス可能
- **セッション管理**: 30分間操作なしで自動ログアウト
- **アクセスログ**: 管理画面へのアクセス履歴記録

### 2.2 将来機能（Phase 2）

#### 2.2.1 リアルタイム更新
- **Supabase Realtime統合**: データの自動更新
- **プッシュ通知**: 重要なイベント発生時の通知
- **ライブグラフ**: リアルタイムでのグラフ更新

#### 2.2.2 高度な分析
- **ユーザー行動分析**: ページビュー、滞在時間等
- **コホート分析**: ユーザーグループ別の傾向分析
- **予測分析**: 成長予測、チャーン率予測

#### 2.2.3 ユーザーフィードバック
- **人気スポットランキング**: ユーザー向け公開情報
- **トレンド情報**: 季節別・地域別の傾向分析
- **レコメンデーション**: 個別ユーザーへの推奨提供

## 3. 非機能要件

### 3.1 パフォーマンス
- **初期表示時間**: 3秒以内
- **データ更新間隔**: 30秒（Phase 1）、リアルタイム（Phase 2）
- **同時アクセス**: 最大5管理者の同時アクセス対応

### 3.2 セキュリティ
- **認証方式**: Supabase Auth（メールアドレスホワイトリスト）
- **通信暗号化**: HTTPS必須
- **データマスキング**: 個人情報の適切な保護

### 3.3 可用性
- **稼働率目標**: 99.5%以上
- **エラー処理**: グレースフルデグラデーション
- **バックアップ**: 統計データの定期バックアップ

### 3.4 保守性
- **コード品質**: ESLint準拠
- **ドキュメント**: 技術仕様書、運用マニュアル完備
- **テスト**: ユニットテスト、統合テストの実施

## 4. UI/UX要件

### 4.1 デザイン原則
- **視認性**: 一目で状況が把握できるダッシュボード
- **レスポンシブ**: PC、タブレット、スマートフォン対応
- **一貫性**: 既存アプリケーションとのデザイン統一

### 4.2 画面構成
```
┌─────────────────────────────────────┐
│  ヘッダー（タイトル・更新時刻）      │
├─────────────────────────────────────┤
│ ┌─────────┐ ┌─────────┐ ┌─────────┐│
│ │システム │ │ユーザー │ │コンテンツ││
│ │ 状態   │ │  統計  │ │  統計  ││
│ └─────────┘ └─────────┘ └─────────┘│
│ ┌─────────────────────────────────┐│
│ │     グラフエリア（Chart.js）     ││
│ └─────────────────────────────────┘│
│ ┌─────────────────────────────────┐│
│ │        詳細データテーブル        ││
│ └─────────────────────────────────┘│
└─────────────────────────────────────┘
```

### 4.3 カラースキーム
- **正常状態**: 緑系（#4CAF50）
- **警告状態**: 黄系（#FFC107）
- **エラー状態**: 赤系（#F44336）
- **情報表示**: 青系（#2196F3）

## 5. データ要件

### 5.1 取得データ
| データ種別 | ソーステーブル | 更新頻度 | 保持期間 |
|----------|-------------|---------|---------|
| ユーザー情報 | profiles | 30秒 | 永続 |
| 旅行記録 | trips | 30秒 | 永続 |
| エラーログ | （メモリ） | リアルタイム | 24時間 |
| アクセスログ | admin_logs | リアルタイム | 90日 |

### 5.2 集計処理
- **日次集計**: 毎日0時に前日分を集計
- **月次集計**: 毎月1日に前月分を集計
- **リアルタイム集計**: 必要に応じてオンデマンド実行

## 6. 制約事項

### 6.1 技術的制約
- **Supabase無料プラン**: API呼び出し制限考慮
- **ブラウザ対応**: Chrome、Safari、Firefox最新版
- **React版**: v19.1.1使用

### 6.2 運用制約
- **初期運用**: 管理者1名での運用想定
- **データ量**: 初期は1000ユーザー規模を想定
- **拡張性**: 将来的な10,000ユーザー対応を考慮

## 7. 成功指標

### 7.1 定量的指標
- **ダッシュボード利用頻度**: 週3回以上のアクセス
- **エラー検知時間**: 発生から5分以内の認知
- **データ精度**: 99%以上の正確性

### 7.2 定性的指標
- **運用効率化**: 日常監視作業の50%削減
- **意思決定支援**: データに基づいた改善施策の実施
- **ユーザー満足度**: フィードバック機能による向上
